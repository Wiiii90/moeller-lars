# Editorial Rich Text contract

**Source boundary:** Scoped inspection through `dev@600a5401d12371bc94bd74008ec72522e6bca466`: `AdminRichText`, `RichTextEditorPlugin`, `artist-rich-image.js`, `artist-rich-spacing.js` and the shared spacing stylesheet. This describes implemented source behavior, **not** an executed test or accepted browser review.

The **single editable visual editor** is `AdminRichText` built on Filament RichEditor/Tiptap. Journal, Home, Custom Pages and nested text content use it rather than separate CV editors, media stores or page-specific editor variants. [Admin controls](../admin/controls.md) own the shared field geometry, [dialogs](../admin/dialogs.md) the mounted Edit dialog and its persistence boundary, and [media](../media.md) the underlying Storage assets. This document owns editor content, tools, image layout and rendering semantics.

## Content and publication

- Stored legacy Markdown remains readable. Editing converts a legacy value to supported visual HTML without a blanket data migration.
- `RichTextDocument` validates the editorial representation and `SafeRichTextRenderer` sanitizes HTML before public rendering. Rich Text does not bypass the owning page/Journal editorial service, audit, notifications or Working-to-Committed publication.
- Changes run through the **one existing Edit action**. Ordinary typing persists on genuine focus loss; explicit tool operations notify that same change boundary. No separate timer, parallel document state, nested Action save or independent undo history.

## Inline links

The shared editor overrides Filament's built-in link tool so a framework `LinkAction` modal is not mounted. Its toolbar opens an inline panel **inside the current Edit dialog** with the selected Tiptap range. The panel can edit and remove a link, insert a link label when nothing was selected and choose an optional new-tab target. It uses the **existing shared round icon buttons** for Remove (only on an existing link) and Close in the popover header, **not** an Apply/Cancel footer. Enter, an actual field exit or the new-tab option applies a complete valid edit through the existing Tiptap document; click-away also attempts the completed edit once. Unfinished or invalid addresses remain uncommitted, and revisiting an unchanged link does not create a second update. Explicit Close/Escape dismiss without inventing a mutation.

Only allowed HTTP, HTTPS and mailto destinations are accepted; `SafeLinkPolicy` enforces the public policy independently. Closing the panel without a genuine edit does not create a separate domain mutation. Link tools share the editor's normal save boundary, not another dialog or timer.

## Image media and layout

The image picker is the existing `MediaAssetSelect`, shown as a searchable, toolbar-anchored Storage selector inside the **same Edit dialog**, not another modal or media catalog. It selects available image `MediaAsset` identifiers; historical `media:` references remain supported. A reused asset is referenced, never copied or owned by the Rich Text field. Uploads belong to Storage; the generic editor's `Attach Files` upload path is disabled. Removing an image from text does not delete its shared asset. Public delivery still checks the [media/rights eligibility contract](../media.md).

`ArtistImageLayout` is the one image-node extension for the editor and the public renderer. It supports exactly these persisted placements: `inline`, `left`, `center`, `right`, `float-left` and `float-right`. Float variants permit subsequent paragraphs to wrap beside an image at sufficient width; narrow layouts clear that float. **In the visual editor, a resizable image's Filament/Tiptap wrapper participates in the position and float layout**; targeting only the nested `img` leaves the resize container in its original position. The shared `admin/forms.css` applies the stored placements to either direct images or `data-resize-container` wrappers; Public output uses the same persisted placement rather than storing a second alignment state. Image controls act on the **selected image node** or the image adjacent to the current cursor, including the existing selected-node fallback, rather than the floating toolbar's focus position. This matters after the image or toolbar takes focus.

Image position/wrapping and the optional **500-character caption** appear only in the contextual image toolbar; ordinary paragraph/alignment tools remain separate. Caption is display text, not an alternative-text replacement. The image toolbar stays inside the visible native dialog scrollport using the existing Floating UI placement. The caption panel stays in the owning Edit dialog; its successful operation dispatches the one canonical change notification **from the editor's own connected shell**, never an orphaned popup.

The same `MediaAssetSelect` handles eligible media for Gallery, Journal, Home, Custom Pages, Rich Text and the site icon. An identifier-backed select offers up to 24 recent available assets initially, and searches filename/alternative text on the server with up to 30 results; relationship-backed choices may use bounded native preload. The native Filament keyboard and selection lifecycle is retained. The insert-image picker closes its selector and panel together on insertion, Cancel/X, Escape or click-away. Clicking outside this popup does **not** close the parent Edit dialog.

## Text color and spacing

Text color uses one toolbar-anchored **inline color popover** in the existing Edit dialog, with a native color swatch and hexadecimal input plus the shared round Remove/Close icon buttons. It changes the text-color mark in the same Tiptap document immediately on a deliberate picker change, avoiding a nested framework `TextColorAction` and a separate Apply button. Clearing the color removes the mark; an unchanged selection/color is a no-op. The public renderer uses the registered extension. This describes the current editor-specific controls, **not** a user-approved replacement for the Admin's existing canonical ColorPicker styling: that visual convergence remains subject to the artist's browser review.

Paragraphs and headings now use **numeric line heights** in the single selector: **1,0; 1,15; 1,5 (default); 2,0**. The selected value applies to the current paragraph or heading and is not a text-selection-only character style: the editor preserves the node type and selection positions while the chooser is open, then updates that block's `artistSpacing` attribute. `ArtistTextSpacing` and `artist-rich-spacing.js` also **read old saved `default`, `none`, `compact`, `relaxed` values** and map them respectively to `1.5`, `1.0`, `1.15`, `2.0`. Default `1.5` is omitted from generated data attributes; the shared `resources/css/rich-text-spacing.css`, Admin editor and public output use the same effective line heights. The spacing control **does not** alter paragraph margins as a side effect. No page-specific spacing algorithm or separate saved format is introduced. **Compatibility is semantic, not pixel-identical:** previously saved `compact` rendered at line height 1.3 and `relaxed` at 1.8 with additional paragraph margins, whereas the new numeric presets use 1.15 and 2.0 without those extra margins. Retaining and reading the old authored values prevents losing content but can change its visible layout. Inspect representative already-published text before calling the visual migration accepted.

Color, link, caption and spacing popovers **use the editor passed by the native Tiptap tool and the owning Rich Text shell's resolved DOM scope**, not a second page-local editor state, sibling Alpine View scope or global editor lookup. The selected editor is retained only as an ordinary shell property outside Alpine's reactive proxy and is used for the subsequent selection-preserving operation. This avoids stale/proxied editor objects while preserving relevant text selection or image identity. Their own native change bubbling is suppressed, so a deliberate tool application emits **the existing Edit dialog's change event** rather than racing it with an accidental extra autosave. Image placement, captions and table structure commands likewise signal the shared mutation boundary; merely entering or opening a popover is not a save.

## Editor transport

Filament maintains a single structured Tiptap document for links, images, nested lists and tables. Deep nested editor updates exceed Livewire's former default dot-path depth of 10; `config/livewire.php` permits depth 24 while preserving the framework's other request-size, call-count and component-count limits. This extends valid transport depth, **not** editor authorization, HTML sanitization or persistence ownership.
