## Operating contract

- Change only testing. Never write to dev, docs or main. Admin/Public chats edit dev independently; the docs workstream owns docs/TESTING.md. Read AGENTS.md, ui-skills.md, tests/README.md and exact production owners before each scoped change.
- Never touch GitHub Actions, jobs, logs, releases, deployments, servers, preview workflows or polling. Pushes on testing must not trigger CI. Integration to dev requires user approval.
- Re-read testing and dev HEADs immediately before a commit. For concurrent changes inspect changed paths and reconcile. Use create_tree + create_commit and CAS update_ref(expected_sha); never force-push. Import new dev changes as genuine merge commits with dev as additional parent, only after verifying file-level conflicts and tree contents. Retain intentionally deleted tests/Architecture.
- No workarounds or redundant production paths. A meaningful test guards observable behavior, authorization, publication Working vs Committed, mutation notification/audit/no-op, rollback or stable domain data. Do not lock arbitrary CSS classes/icons, internal table structures, magic constants, query budgets, historical implementation accidents or source text.
- All DB tests require a verified disposable PostgreSQL testing database and the unchanged LocalPreviewDatabaseGuard: GITHUB_ACTIONS=true, MOELLER_LARS_DISPOSABLE_TEST_DATABASE=1, and no persistent-preview flag. Never bypass this guard on an existing local preview or production DB. BrowserProfilingSeeder has the same protection.
- Mark each conclusion SOURCE-REVIEWED, TEST-AUTHORED, TEST-RUN or BROWSER-VERIFIED accurately. Update this living file in the same commit as substantive testing changes. Replace obsolete status and priorities rather than accumulating another dated work log.
