## 5. Only acceptable future public-media architecture

- **Current owner:** `MediaIngestService` saves immutable `originals/<uuid>.<ext>` with SHA-256 and GD-generated WebP `variants/<uuid>-thumbnail.webp` (max 960px, `public-v1`). `MediaVariantRegenerationService` regenerates only exactly matching legacy `public-v1` bytes; it cannot silently alter this format behind an existing URL. `MediaCapacityService` counts `originals/` authoritative, `variants/` generated and database usage. Avoid uncontrolled disk doubling.
- `PublicMediaController` currently authorizes through `PublicMedia::isPublicAsset/isPublicVariant` and serves *archive original* or legacy thumbnail via `X-Sendfile`, SHA-based ETag and `Cache-Control: public, max-age=31536000, immutable`. Existing URLs are stable IDs; **cannot mutate bytes at those same immutable URLs** after metadata edits. Preview uses separate existing routes and publication read context. Respect byte range / `X-Sendfile` ingress semantics.
- `PublicationSnapshot::TABLES` includes `media_assets`, `media_variants`, `public_content_settings`. `PublicationService` copies staged `public` into `committed`; `PublicationVersionService` captures historical row snapshots/restores and does stage reset/revert; `PublicationMediaCleanupService` preserves assets referenced by `committed` or historical version rows before physical deletion. Asset rights edits and inherited General notice affect publication meaning. No new file can be deleted while a live, preview or restorable historical version may refer to it.
- Next architecture after tests pass: **one** versioned artifact owner/manifest (full-resolution rights-bearing copy plus tagged existing-thumbnail equivalent) keyed by authoritative image hash + effective rights revision + transform version. Stage and verify to private immutable keys, guarantee capacity, then associate with existing publication owner **atomically**, including working/committed/historical states and Undo. Publication references and revisioned URLs/ETags must change when metadata changes; old immutable URLs must serve old bytes for valid active/historical consumers or be correctly revoked, never point to new bytes. Make backfill bounded, restartable, idempotent and capacity-accounted; no request-time ExifTool, new gallery pipeline, timer or polling. Preserve public authorization and the existing non-image behavior.
- Required scenarios before activation: explicit and inherited copyright changes (including General default), explicit `none`, third-party photographer, pre-existing conflicting tags, media deletion and restore, preview, commit/Undo/stage reset, public vs private permissions, duplicate/no-op rights save, source integrity, checksum/ICC/full quality, tagged thumbnails, old/new URL+ETag+cache, X-Sendfile, idempotent backfill, quota and cleanup.
