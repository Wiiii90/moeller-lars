# Dev Worker 8 — Shared Admin dialog and Media selection

**Branch:** `dev`
**Lease:** 15 (active)
**State:** Central draggable/resizable Admin dialogs source-prepared; runtime/browser acceptance required.

## Canonical ownership and protected behavior
- Shared Admin dialogs are native Filament Actions via `app/Filament/Support/Dialogs/AdminDialog.php`. The shared presentation owners are `resources/css/admin/dialog-contract.css`, `resources/css/admin/dialog-interactions.css` and `resources/js/admin-dialog-geometry.js`. Never create per-page dialog controllers, extra scroll locks, a second close/focus mechanism or another persistence owner.
- Native Filament focus trap, X/Escape/backdrop lifecycle, saved scroll position, nested popovers, editor autosave and long/short-page body locking are protected. The existing patched Filament Support scroll-lock script stays intact. All Admin/Public root, Sidebar, popup and dialog scrollbar chrome is deliberately hidden while native scrolling remains functional.
- All five shared dialog meanings (Create, Edit, Command, Confirm, Viewer) and framework-owned security dialogs retain their existing semantics. Dialogs default to their original canonical width and top-aligned content frame. General/Stage, Gallery, Journal, Home, Pages and Storage domain-specific actions stay with their respective workers.
- The user reports that transiently displaced/offscreen dialogs can become impossible to edit. Moving/resizing is both a user-requested workflow and a recovery affordance; it does not excuse leaving a dialog outside the viewport or adding a separate body/window positioning system.

## Current implementation — movable/resizable dialogs (2026-11-20)
- On `dev`, extended **the one existing** `admin-dialog-geometry.js` to keep a modal-ID-scoped, in-memory position and manual size during its current open session. CSS custom properties on the native modal own only the window offset (relative `left/top`) and explicit size. No ancestor/backdrop transforms or additional scroll/wheel locks were introduced. Filament's native animated `transform` remains untouched.
- On fine-pointer desktop viewports (wider than 46rem), users can drag the native dialog header, resize using the bottom-right shared grip, use Alt+arrow keys while the header is focused to move, or arrow keys on the focused grip to resize (Shift increases steps). Form fields, header action buttons, close and popup controls are excluded from dragging. Touch/mobile retains the original non-draggable responsive presentation.
- Window moves/resizes are bounded to the measured post-Sidebar admin Main frame below the topbar. The frame calculation now clamps the topbar reserve in very short viewports. Resize retains the original top-left anchor; shrinking the viewport or morphing a Livewire dialog reapplies/clamps its session to prevent unreachable offscreen placement. New modal open starts at canonical initial dimensions and position; close/navigation clears session data.
- Shared `dialog-contract.css` owns the affordance styling and explicit manual-width/height rules (including a visible, keyboard-focusable corner grip) without creating a new dialog family. The native content remains the only inner scroller. Existing modal enter/leave animation, backdrop and root scroll lock remain in place.
- No new library/package, domain form schema, public navigation, tests, deployment or cross-branch change is in this scope.
