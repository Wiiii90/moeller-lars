## Current ownership and accepted user decisions
- All Admin dialog categories remain native Filament Actions via `app/Filament/Support/Dialogs/AdminDialog.php`. Single shared presentation owners: `resources/js/admin-dialog-geometry.js`, `resources/css/admin/dialog-contract.css`, and shared admin controls. Never replace Filament's close, focus/Escape, validation/autosave, stacking/backdrop or scroll-lock lifecycle; no per-page dialog geometry.
- On desktop with fine pointer, dragging the dialog's header and Alt+arrow keys on its focused header move the native window. Header actions, close button, fields and links retain their own interactions. Mouse-only touch/mobile returns to fixed native responsive presentation.
- **New user decision (2026-11-20): Remove manual dialog resizing completely.** Delete grip, manual width/height CSS, resize keyboard handler and associated JS. Resizing the browser viewport must still re-clamp a deliberately moved window.
- Add a restrained, subtly tinted title bar with a single 1px horizontal bottom border spanning the entire header, including the contextual action region. This visually separates heading/controls from dialog content without an extra parallel header.
- **Critical correction:** After the first drag/resize implementation, dialogs opened far right, mostly outside the screen. Preserve the native horizontal Filament geometry and never apply drag coordinates or speculative clamping to an untouched modal during mount. The user now prefers the dialog **vertically centered within the usable Admin Main frame** rather than anchored at its top. Maintain internal scrolling for tall forms.

## Current source change — native starting frame plus deliberate drag
- Rebuilt the geometric extension on top of the already accepted **pre-drag** `resources/js/admin-dialog-geometry.js` and `dialog-contract.css` (baseline `dev@5aa48a4`). ## Shared Exhibition date controls (2026-11-20)
- User screenshot: `Starts` and `Ends` in Edit Exhibition show oversized/unnormalized labels; both Partial-Date popovers remain open when switching between their triggers, but clicking `Vernissage` dismisses the first. User requested centralized correction and asked whether Vernissage is central and why its calendar icon is absent.
- Root cause: canonical `AdminPartialDateControl::make()` returns a raw `ViewField` without `AdminControl::decorate()` (unlike canonical Admin field labels); the teleported `admin-partial-date-control.blade.php` click-outside handler excluded **all** `.admin-partial-date__trigger` elements, not only its own trigger. Thus a click on another Partial-Date trigger suppressed the first popover's dismissal, inadvertently allowing two popovers.
- During this integration another worker published the shared `AdminPartialDateControl::make()` decoration on `dev`; retained that existing implementation without a competing edit. It applies `AdminControl::decorate()` to its `ViewField`, preserving optional `AdminHelp`, metadata, ISO partial-date persistence and region. The teleported popover's outside handler checks only `$refs.trigger.contains($event.target)`; changing fields now closes the previous popup, including transitions to Filament Vernissage. The own trigger still toggles its own popup, no new global event/listener or duplicate close owner.
- `Vernissage` already uses native Filament 5 non-native `DateTimePicker` configured in `AdminControl::register()`. Its Filament picker/popover are central and remain framework-owned. The global DateTimePicker configuration now supplies an inline suffix `heroicon-o-calendar-days` icon only for controls with `hasDate()`, so pure time-only fields do not receive a misleading calendar. Its date/time save and timezone/format semantics remain unchanged.
- Verification: inspected upstream Filament 5 DateTimePicker's native `suffixIcon(..., isInline: true)` support and built-in click-outside behavior; isolated the Partial-Date outside expression: own trigger does not close through click-outside, another field and Vernissage trigger do. Source only: no live browser visual or actual multi-popover behavior observed after change; no tests, CI, deploy or Preview run.
- Browser review: open Starts then Ends (Starts closes); open Ends then Starts; switch either to Vernissage; own-trigger toggle, outside click and Escape; no stale overlap after scrolling; coherent uppercase small labels including light/dark optional Help; calendar icon visible on Vernissage (also other DateTimePicker date fields) but not pure time fields; verify choice, clear, correct partial-date ISO, Edit autosave exactly once and no regression to Filament date-time save.

## Unified Create dialog controls (2026-11-20)
- User approved a UX trial for all **new-object form dialogs**: consistent Plus icon before each Add/Create launcher, a **plain Check glyph within the existing circular header icon button** (no second drawn circle), Submit as **rightmost** title-bar action, Filament's native X immediately to its left, and other actions (such as Clear) farther left. Motivation: a rightmost X can be mistaken for autosave-close, silently discarding uncommitted Create state.
- Scoped to canonical `AdminDialog::create()` and its `admin-dialog--create` window class. It now sets the opener `AdminIcon::Add` (`heroicon-o-plus`, forced before label) and the commit action `AdminIcon::DialogSubmit` (`heroicon-o-check`). Removed the optional Create-specific submit-icon argument so the same icon is guaranteed for all creators. Updated the sole known explicit Create icon override in `ManagesSitePageCreateDialog` (previously `AdminIcon::Pages`). The private `committedTask()` still supports separate icons for **Command/Confirm** and the existing optional onClear callback.
- Filament 5 itself renders Create modal footer actions in `Submit, extra footer actions…` DOM order, and its native X separately in the modal header. The shared dialog CSS now reverses only the Create action rail, places Submit at the right-side inset, moves native X one button-width plus one gap to its left, and reserves that X slot between Submit and the next additional action. For a 32px button and 8px gap, the visual right-to-left order is Submit – 8px – X – 8px – Clear. Existing class-based header reserve for total action count is unchanged. No duplicate close/submit element, event handler, DOM rewrite, scroll lock or global action reorder.
- **Preserved semantic contract:** Create submits once through Filament validation/domain mutation and closes on success. Native X/Escape/backdrop still cancel/discard uncommitted Create form; it does NOT silently save. Edit dialogs remain autosaving and keep their prior X/rightmost rail, Confirm/Command/Viewer retain their prior icons and order. This is a visual affordance experiment, not a persistence behavior change.
- Static evidence: compared upstream Filament 5 `CanOpenModal::getModalFooterActions()` and `modal/index.blade.php` to verify Submit-first order and native X ownership; verified `AdminIcon` enum has both icon aliases and the shared Create class is applied by `AdminDialog::base()`. No browser/real PHP runtime check or CI was run.
- Browser acceptance: inspect Add Artwork/Exhibition/Page/Social link/Create related forms: Plus before opener label, plain check glyph in the far-right Create Submit's existing round button (only one circle), native X immediately left, Clear further left, no click-target collisions, correct focus/tooltip/color, validation failures keep form mounted, native X discards and Submit actually creates exactly one object; verify both narrow and wide dialogs in light/dark, compare Edit/Confirm unchanged.
