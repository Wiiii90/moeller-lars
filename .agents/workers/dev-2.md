## Required invariants (user-approved 2026-11-03)
1. Working artist content, registered originals and every required available thumbnail/poster stay coherent through upload, linking, reuse, delete and recovery. **Registered but unassigned media is legitimate**, not a zombie.
2. A **true zombie** is a physical media file with no Working, Committed, retained-history, deletion-outbox or active-upload owner. Logically deleted files retained for legitimately protected Activity/Publication do NOT count as zombies; Activity/Undo will be intentionally cleared before release, not used as an excuse for permanent architecture.
3. **Free Storage never destroys required thumbnails**, never triggers libvips from an HTTP request, and only removes eligible former restore/Undo data, explicitly deleted media and proven orphaned/stale staging.
4. A single authoritative thumbnail reader/writer; no permanent pre-release `public-v1`/`public-v2` variants or on-request regeneration. Preserve persisted artist data and any genuine Committed/recovery ownership until a controlled data cutover proves safe.
5. Preserve deliberately generous upload and image-size requirements. No arbitrary new general file/pixel cap. Cross-filesystem+PostgreSQL completion must be durably reconciled rather than falsely claimed physically atomic.
6. Only the Testing worker authors/executes regression tests on `testing`. Dev Worker 2 records **grouped** acceptance work here, not per-commit test files.

## Grouped handoff to Testing worker (NOT authored/executed here)
**A. Reference and deletion integrity**
- Home active/inactive List direct media and List-item rich text, Custom Page top-level List + decorative Image children with Text/List rich media, nested inactive/published flags; PublicMedia eligibility equals canonical reader.
- Removing a file with multiple uses clears only that reference; cannot silently remove child content. Leave unrelated Working/Committed/history entries intact. Recheck catches surviving reference and rolls back transaction. Concurrent delete/link mutation and mixed-asset physical-delete key list fail closed.
- Registered unassigned media remains in Storage and retains preview; logically deleted-but-publication-protected original is retained appropriately, not misclassified as orphan.

**B. Physical media, previews, Free Storage**
- Original+preview stored and independently integrity-verified across JPEG/PNG/WebP, H.264 MP4 and WebM poster, supported audio; 500MP and agreed per-site byte limits not tightened. High-res progressive JPEG rejection occurs before libvips OOM; ordinary large source processing still governed by actual runtime envelope.
- Free Storage clears only approved Undo/history candidates and eligible logical deletes, never any available thumbnail or poster. No hidden libvips/FFmpeg on public/admin preview routes. Missing/truncated variant blocks readiness honestly. Duplicate preview-kind rows fail closed.
- Bounded orphan sweep: unregistered old canonical file removed; registered unassigned, new/in-flight, Committed, snapshot, rights artifact, outbox and unrecognized file retained; filesystem/DB errors fail closed. 48h stale staging cleanup and an interrupted sweep recover correctly. Storage dashboard/notification counts never falsely announce completion.
- Existing historical `public-v1`/`public-v2` persisted `transform_profile` metadata still readable by **one** reader. Verify that live artist database has no duplicate preview kinds before any format/column migration.

**C. Upload transaction, session identity and recovery**
- 16MiB chunk success, partial-write rollback, chunk/manifest write failure, lost `finish` acknowledgment after canonical commit, retry without creating duplicate original, file absent/preview missing and corrupted existing MediaAsset cases.
- Modified **middle** bytes with same filename/size/mtime/first/last sample fail resume via per-chunk SHA256; completed receipt with changed file starts new transfer without deleting original; a canceled incomplete upload frees staging and reservation.
- Concurrent uploads/dedup, idempotent finish, client/session user authorization, expired manifest, physical partial cleanup and recorded server exception category. Observe database+filesystem consistency, not only an HTTP 200.

**D. Notifications / admin browser acceptance**
