## 2026-11-03 — Read-only media/upload architecture audit
**Source baseline inspected:** `dev@d54d2afb184cc7f6f01db0d8a28ca9d7b0ffefab` (other Dev workers continue changing disjoint files). No application code, test files, docs, deployments, or artist media changed during audit.

**Verified design:**
- One `MediaIngestService` stores immutable UUID-named private originals and separately stored 960px WebP image thumbnails/video posters, each recorded with SHA-256 checksums; authoritative SHA-256 deduplication checks plus DB transaction and best-effort filesystem rollback; private `incoming-media` stages 16 MiB chunks and reserves remaining bytes against whole-site quota.
- `MediaCapacityService` counts all private media including staged parts/variants and persistent PostgreSQL footprint, plus open-session remaining-byte reservations; separate host free-space reserve 256 MiB. Current operator quota controls byte admission. A standalone original's file byte-size is **not** a memory guarantee.
- Image formats JPEG/PNG/WebP, video H.264-MP4 and VP8/VP9/AV1-WebM, audio MP3/M4A/Ogg/WAV. Original remains intact, image/WebP preview max edge 960; video poster 960, original video not transcoded.
- `ResumableMediaUploadService` has 48-hour expiry, bounded cleanup batch, run on new `begin()`, plus daily `routes/console.php` schedule declaration; deployment activation of Laravel scheduler remains unverified.
- `PublicationMediaCleanupService` has durable delete outbox and separately respects Working/Committed/historical publication ownership; Storage breakdown identifies uncatalogued originals but that does not prove automatic orphan cleanup.

**Source-confirmed risks / follow-up:**
1. **High — safety bypass:** `MediaVariantRegenerationService::renderExpectedBytes()` calls `imageThumbnail()` directly, without `assertImagePreviewCompatible()`; deleted/rebuildable image variants or Storage Free-storage can re-trigger 384 MiB out-of-memory from retained progressive originals. Generated variants also bypass `MediaCapacityService::assertCanStoreGenerated()` when re-materialized.
2. **High — verification OOM:** `MediaIntegrityService::checkFile()` calls `$disk->get($key)` for complete originals. With application PHP memory_limit 128 MiB this is not safe for multi-hundred-MiB media; `media:verify` also inspects registered media only, not an unregistered file under `originals/`. Correctly deferred deletion can be misclassified as `deleted_original_present`.
3. **High — reference/deletion symmetry:** `MediaReferenceQuery::mediaIdsForHome()` and `MediaAssetEditorialService::removeHomeReferences()` skip List components; Custom Page Image-child rich text references are not traversed by `RichTextMediaReference::idsFromCustomPageBlocks()`; `PublicMedia` does not authorize direct Custom Page List media IDs. Consequently `isReferenced`/physical cleanup may miss a still-used media asset. Coordinate with Dev Worker 4 and reference/public domain owner before changing deletion.
4. **High — resource policy:** 500 MP accepted maximum for images generally and no bounded video-frame dimensions; only >16 MP progressive JPEGs get special early rejection. No safe peak-memory guarantee for large PNG/WebP, ordinary JPEG, smaller progressive JPEG or huge video frames inside Validation's 384 MiB RAM (768 MiB RAM+swap) and ~0.75 CPU; 120s converter and 30s probe timeouts. Quota-derived per-file byte maximum can approach full site allowance (operator initially 5 GB), chunking bypasses legacy PHP post ceiling.
5. **Medium — resumability / ambiguous completion:** Client resume identity hashes file metadata plus first/last 64 KiB, not the entire file; different middle bytes with same name/size/mtime/front/back can share a staged session. A successful DB/physical commit followed by failed manifest write can leave `/finish` ambiguous and trigger false failure/re-upload despite canonical asset existing.
6. **Medium — staging/orphans:** Failed high-res progressive finalization retains complete `.part` until expiry; pruning executes on another upload start or on an independently activated scheduler. Host scheduler and live staging inventory unverified. Cleanup exceptions can leave uncatalogued physical originals/variants; no automatic general orphan reaper established. Check with read-only inventory; never delete artist files blindly.
7. **Medium — notification/UX:** Shared formatter is good, but native file-field `/failure` truncates posted message at 400 characters and may cut a long-filename rejection instruction; saved-but-unlinked file still gets generic “Upload failed” title. Unknown errors, duplicate delivery after lost response, unsynchronized live status and multi-file summaries require browser cardinality tests.
8. **Medium — verification drift/docs:** `tests/Feature/Admin/Gallery/GalleryUploadsTest.php` still submits `UploadedFile` objects to `primary_upload`, while current `ResumableMediaField` forms expect an already ingested integer MediaAsset ID; likely stale/incompatible tests (not run). No identified existing automated JavaScript upload-transport suite. `docs/media.md` describes a retired direct Livewire upload flow; server-platform capacity guide describes originals-only allowance while actual code/site doc charge entire site incl generated files and database. Historical public-v1/GD is deliberate immutable-media compatibility, not automatically dead code.

**Safety and acceptance:**
- Audit was connector-based source reading plus historical user-supplied read-only Validation evidence (one 97.7 MP progressive JPEG triggered container OOM); NO currently executed runtime tests, no active app browser and no current server inventory, no deployment.
- Visual/interaction acceptance belongs in local browser with a disposable media/database seed; real resource-pressure tests in an isolated 384 MiB container with comparable CPU/swap, **not** artist's protected Validation media. Validation can later receive user-authorized read-only presentation parity checks.
- Recommended staged correction: unify preflight and resource limits for initial and regenerated previews; streaming bounded integrity verification; fix canonical reference/query/removal symmetry with Dev Worker 4; strengthen resumable identity, commit receipt and orphan inventory; address feedback truncation; Testing worker owns focused tests on `testing` before gated browser acceptance.
