## Controlled race investigation

The existing Filament Select sends `getOptionsForJs` and related lookup calls through `callSchemaComponentMethod` with `async: true`. The exposed option method is renderless, but its response still carries a Livewire component snapshot. `AdminDialog::edit()` owns autosave through `wire:change="callMountedAction"`; the Custom Page action validates the previously opened component against the persisted component and updates `editingComponentOriginal` after a successful save. Livewire's request coordinator explicitly lets asynchronous actions overlap ordinary actions and its snapshot merge replaces `snapshotEncoded`, `snapshot` and canonical data with each arriving response. The documented interceptors expose request/action lifecycle observation and cancellation, but no supported stale-snapshot merge or ordering policy for this pair has been established. Selectively overriding Filament's async metadata or adding another client request queue would require a new coordination path and has not been accepted as a canonical fix.

The existing browser suite now contains a controlled response-order test: a genuine `getOptionsForJs` response is held until the first edit has been saved, then released before the second edit. Against the existing implementation it fails in both Chromium and desktop WebKit because reopening retains `First saved edit`, not `Second saved edit`. Command: `RunPublicationConcurrency.ps1 -QualificationSuite Browser --project=e2e-chromium --project=e2e-webkit-desktop --grep 'delayed Storage options response' --reporter=line --output storage/framework/testing/browser-race-controlled`. Both failures are expected evidence of the unresolved product defect, not successful qualification. A separate browser scenario using two independently opened editor pages passed in both engines and verified that a genuine stale edit is rejected while the first persisted edit survives; use the same runner and projects with `--grep 'independent editors reject' --output storage/framework/testing/browser-race-conflict`.

Upstream PR 10840 changes the canonical value used when computing reactive differences to the value captured when the request was sent. Its proposed diff does not change the unconditional replacement of the signed `snapshotEncoded` and canonical snapshot by the later response. Therefore, from source inspection it does not establish that our next save carries the newer `editingComponentOriginal`; its own test covers a different live-input sequence. It was not applied, and no claim is made that it fixes this race.

Next: identify a supported owner-level correction for stale asynchronous component snapshots, keeping the native picker, the existing autosave owner and independent-editor conflict detection. Re-run both controlled browser scenarios in Chromium and WebKit on the correction before the full qualification. Until then the intentionally failing race test must remain visible and the final qualification remains open.

## Owner and isolation options

Filament 5.7.6 hardcodes asynchronous `callSchemaComponentMethod` for dynamic Select options, labels and searches; no supported per-Select serialization option was found in the installed component. Livewire 4.4.0's normal coordinator explicitly permits actions marked async to overlap, and `#[Renderless]` and `#[Json]` skip rendering rather than providing an independent signed component snapshot. A real failed trace shows the delayed options request also carried pending `mountedActions.0.data.body` updates, so discarding every such response as if it were stateless would lose legitimate updates. Livewire islands share the parent component state and are not independent snapshot isolation.

Filament provides `Filament\Schemas\Components\Livewire::make()` for a genuinely nested component. A child can own the existing canonical `MediaAssetSelect` and its own snapshot, but the current `afterStateUpdated` closure directly invokes the owning RichEditor object's commands; moving that selection across the child boundary requires a new, explicitly scoped handoff and verification of editor identity, authorization, focus, modal lifecycle and all shared Rich Text consumers. This would change architecture and has not been implemented or verified. The canonical picker and storage option query must remain singular.

The other owner is Livewire itself: framework-level handling must keep a superseded read response from replacing a newer signed snapshot while still delivering its result and accounting for any updates that accompanied it. An alternative is a formally supported Filament/Livewire read-only request facility that does not submit or replace parent component state. Either requires framework support or a specifically approved framework-level change. PR 10840 changes the reactive diff base but does not establish this snapshot-order guarantee. Do not apply it unverified. These are proposals, not demonstrated fixes; the controlled browser tests and independent-editor conflict test remain mandatory after the chosen change.
