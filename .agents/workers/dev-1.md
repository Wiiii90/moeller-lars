## User decisions and ongoing proposal (2026-11-22)

- **Implemented in source:** The Exhibition Settings Stage and dialog no longer offer Default Gallery Presentation. Blog continues to own its separate default.
- **Implemented in source:** One central **Activate Defaults** panel holds two compact checkboxes, Enlarge images on click and Show video playback controls. The new persisted switch defaults on for existing Journals and off restores native values (image viewer off, video controls on).
- **Implemented in source:** Global Exhibition Gallery default and both Vernissage visibility defaults are retired. The Exhibition Gallery has only its per-entry panel switch; Vernissage has no visibility switch.
- **Vernissage decision:** On 2026-11-22 the artist explicitly removed the global and per-Exhibition hide-until-start behavior. Any recorded Vernissage date or historical opening text remains visible without a cutoff. Forward-only column-drop migration `2026_11_22_163000_retire_exhibition_vernissage_visibility.php` needs fresh/incremental schema verification.
- **Still only proposals, not approved:** Separate **Exhibition page presentation** from per-Exhibition gallery presentation. Prefer one page-layout preset rather than a cluster of unrelated toggles: current **Catalogue**; alternative **Editorial rhythm** (stable alternating left/right media and restrained larger/smaller emphasis); optional later **Gallery-led** (more prominent gallery). A single **Regular / Varied** choice might be warranted only if the preset itself cannot express rhythm. Any "randomness" must be deterministic per entry and stable between page loads; no jumping layout, no media-order changes and no per-item surprise overrides.
- **Vernissage Stage parity:** The Stage currently offers Starts/Ends but not its existing per-Exhibition Vernissage datetime input, unlike Edit dialog. Visibility policy is now **always show a recorded Vernissage**, per artist; do not recreate a switch without a new explicit decision. Whether Vernissage datetime should be offered in Stage remains open.
- The Stage directory quick-add modal uses Filament's schema-level setter injection (`$schemaSet`) to update the owning Stage form, not its nested modal form. The new Exhibition Stage directory fields accept unlisted names; publication-time EditorialService resolves/creates the independent catalog records in the same transaction. Stage native datalists suggest existing names and retain full-details quick-add dialogs. A new draft is embedded chronologically in the Public preview, focused via `#exhibition--1`. Admin/Public/Stage share `ExhibitionChronology`: exact Current first by nearest end, imprecise year/month overlapping today next, Upcoming by nearest start, Past by latest end descending, undated last; IDs break ties. Exhibition manual ranking, drag sorting and move actions are retired; Blog manual ranking is unchanged. The forward migration `2026_11_22_170000_retire_exhibition_manual_position.php` drops Working/Committed position columns, preserving historical checkpoint payloads.
