# Tests, verification and environment isolation for agents

**Canonical test architecture:** [Testing documentation](../../docs/TESTING.md), current `tests/README.md` and `tests/Pest.php` on `dev`. One shared test architecture across current branches: `dev` contains integrated/interim tests, while the actively maintained `testing` branch curates the intended canonical suite for controlled reintegration before cutover. Its layers are PHP Pest Unit, Integration, Feature, Migration; JavaScript, browser Component/End-to-End/Profiling; and two dedicated multi-process PostgreSQL 17 runners for Publication and Session races. There is no obsolete Architecture suite or independently invented second test architecture.

Use **targeted tests of durable behavior**, not a regression file for every repair iteration, decorative button location, CSS class name or branch-specific scenario. Protect Working versus Committed, authorization, audit/Undo, media integrity, notifications only on actual successful changes, no-op paths, real HTTP/session semantics and concurrency where justified. A written test is not an executed test, and a component test does not prove actual browser drag/popup gestures.

**Isolation is mandatory:** database-writing or destructive tests only on fresh independently verified disposable PostgreSQL 17 (own database/user/loopback port/tmpfs and no persistent mounts). Confirm actual SQL connection/version/cluster, clear inherited `DB_URL` and cached config, isolate media, sessions, logs, views, caches and temp directories. Never use the persistent local Preview database/volume, the artist-curated Validation database, Production or a mere `APP_ENV=testing` string as evidence of isolation. Public Session races need their HTTP/database-session runner; ordinary Pest does not establish that behavior.

**No Continuous Integration (CI) interaction** without separate explicit authorization, including status or log reads, dispatch, cancellation or retries. Release qualification, `main` promotion and deployment are separate. Report **source-reviewed**, **test-executed**, **browser-reviewed**, **artist-accepted** as distinct levels. If a test cannot safely run, report that instead of making a pass claim.

The Test worker owns the accumulated `dev` diff since the last integrated baseline, not a 1:1 regression file for each Dev commit. Before new tests, reconsider the architecture and grouping of the **whole affected test suite**, including fixtures and framework changes. Routine testing-branch reconciliation can happen alongside Dev development, but the **Codex/native full verification, corrections and final isolation checks happen immediately before user-authorized integration after Dev freeze**. A source comparison never substitutes for those final executed checks. The canonical testing method and layer definitions belong to [Testing](../../docs/TESTING.md); do not create another skill file.
